**Écran rond GC9A01** — Afficher localement des informations Natulib sur un petit écran rond.

> **État de documentation :** informations issues du catalogue existant et du firmware Natulib OS V0.448. Le statut historique « Validé » est conservé ; les essais ci-dessous restent à consigner.

## 🌱 À quoi sert ce module ?

Afficher localement des informations Natulib sur un petit écran rond.

## 🔌 Branchement

Raccorder les broches SPI, d’alimentation et de commande conformément à la variante GC9A01 et au plan de la carte.

**Avant toute connexion :** couper l'alimentation, identifier la variante exacte et vérifier la tension et les GPIO utilisés. Les GPIO4/5 des anciens exemples de câblage I²C ne doivent pas être considérés comme une recommandation universelle pour ESP32-C6.

## 🚀 Installation dans Natulib OS

1. Brancher le module hors tension, puis ouvrir l'interface web Natulib.
2. Dans Hardware, ajouter l’écran pris en charge puis configurer son brochage ; utiliser Studio pour personnaliser l’affichage.
3. Vérifier le résultat dans **Accueil** ; consulter **Console** et **Maintenance** en cas d'erreur.

La configuration se fait depuis l'interface, **sans modifier de code Arduino**.

## 📊 Mesures ou fonctions

Affichage de données, états et écrans configurés dans Natulib Studio.

*Les préfixes de mesures dépendent de l'identifiant donné au module dans Hardware.*

## 🧩 Configuration JSON d’usine

Extrait **exact** de `DEFAULT_ORG_SCREEN_GC` dans `factory_defaults.h` (firmware fourni, V0.448), mis en forme pour la lecture. Il s’agit d’un **exemple**, pas d’un relevé de ton montage : contrôler les broches avant branchement.

```json
{
  "id": "visage",

  "category": "sys",
  "type": "screen",
  "driver": "gc9a01",
  "invert": true,
  "pins": {
    "sclk": 18,
    "mosi": 19,
    "dc": 23,
    "cs": 7,
    "rst": 22,
    "blk": -1
  },
  "interval_ms": 30,
  "width": 240,
  "height": 240,
  "use_sleep_mode": true,
  "mA": 60,
  "help": "driver: gc9a01, st7789, ili9341<br>invert: true/false",
  "wiring": "⚡ Câblage : VCC→3V3 | SCL→18 | SDA→19 | RES→22 | DC→23 | CS→7",
  "factory": true,
  "icon": "🖥️",
  "metrics": [],
  "actions": [
    {
      "id": "on",
      "label": "Allumer l'écran"
    },
    {
      "id": "off",

    },
    {
      "id": "diag",

    }
  ]
}
```

### Comprendre les paramètres

| Paramètre | Signification |
|---|---|
| `id` | Identifiant unique du module ; sert de préfixe aux mesures et dans les Synapses. |
| `name` | Nom visible dans l’interface. |
| `category` | Famille utilisée pour organiser les modules dans l’interface. |
| `type` | Type de driver sélectionné par Natulib OS. |
| `driver` | Pilote d’écran sélectionné. |
| `invert` | Inverse la logique du signal lorsque cette option est gérée par le driver. |
| `pins` | Association entre les fonctions électriques et les GPIO ; **adapter au câblage réel**. |
| `pins.sclk` | Horloge SPI. |
| `pins.mosi` | Données SPI de l’ESP vers le module. |
| `pins.dc` | Sélection données/commande de l’écran. |
| `pins.cs` | Sélection du périphérique SPI. |
| `pins.rst` | Réinitialisation matérielle de l’écran. |
| `pins.blk` | Commande du rétroéclairage ; `-1` signifie non configurée. |
| `interval_ms` | Intervalle de mesure demandé, en millisecondes (1 000 ms = 1 seconde). Le comportement exact dépend du driver. |
| `width` | Largeur de l’affichage en pixels. |
| `height` | Hauteur de l’affichage en pixels. |
| `use_sleep_mode` | Autorise le mode veille de l’écran selon le pilote. |
| `mA` | Consommation indicative saisie dans le catalogue, **pas une mesure électrique certifiée**. |
| `help` | Aide présentée par le catalogue d’usine. |
| `wiring` | Indication de câblage proposée dans le catalogue ; à vérifier pour la carte précise. |
| `factory` | Marqueur de configuration proposée par le catalogue d’usine. |
| `icon` | Icône du module dans l’interface. |
| `metrics` | Liste descriptive des mesures exposées dans Natulib OS (identifiants, intitulés et unités). |
| `actions` | Actions proposées dans l’interface et utilisables selon le driver. |

Pour débuter, utiliser l’onglet **Hardware** de Natulib OS : il génère la configuration. La modification manuelle du JSON est facultative.

### 🔌 Câblage

| GC9A01 | ESP32-C6 | Fonction |
|---|---|---|
| VCC | 3V3 | Alimentation |
| GND | GND | Masse |
| SCL | GPIO18 | SPI — SCK |
| SDA | GPIO19 | SPI — MOSI |
| RES | GPIO22 | Reset |
| DC | GPIO23 | Data / Command |
| CS | GPIO7 | Chip Select |
| BL | GPIO2 ou [NL-401A](./NL-401A-PowerSwitch.md) | Rétroéclairage |

> ⚠️ **Alimentation 3,3 V uniquement. Ne jamais connecter VCC au 5 V.**

> ⚠️ Certains GC9A01 conservent le rétroéclairage actif malgré une mise en veille logicielle.

> 💡 Les GPIO indiqués ci-dessus sont une **recommandation par défaut**, utilisable telle quelle pour un montage isolé. Dans une station qui combine plusieurs modules, le câblage réel peut différer : reportez-vous au plan de brochage de votre fiche **[Projet](../Projets.md)**.

### ⚙️ Configuration Natulib OS

**Type :** `screen` · **Pilote :** `gc9a01`

```json
{
  "id": "visage",
  "type": "screen",
  "driver": "gc9a01",
  "pins": {
    "sclk": 18,
    "mosi": 19,
    "dc": 23,
    "cs": 7,
    "rst": 22,
    "blk": 2
  },
  "active": true,
  "debug": false
}
```

| Paramètre | Fonction |
|---|---|
| `driver` | Pilote (`gc9a01`, `st7789`, `ili9341` ou `ili9488`) |
| `pins` | GPIO utilisés par l'écran |
| `active` | Active / désactive le module |
| `debug` | Journalisation SPI sur USB |

> 🔵 **À confirmer / divergence connue** — Le firmware actuel de Natulib OS **force l'inversion des couleurs en dur** (`tft.invertDisplay(true)`) et ne lit pas de champ `invert` dans la configuration du module `screen`. Un champ `"invert"` peut donc être présent dans un fichier `/dev/screen.json` existant, mais il est actuellement **sans effet**. Voir **[Drivers](../natulib-os/drivers.md)**.

### 🛠️ Montage en 5 minutes

1. Préparez les **8 câbles Dupont**.
2. Connectez l'écran à l'ESP32-C6 selon le tableau de câblage.
3. Vérifiez toutes les connexions, en particulier **VCC → 3V3**.
4. Mettez sous tension et téléversez le firmware.
5. Vérifiez l'affichage de l'interface Naturochi.

---

### 🧩 Problèmes courants

**L'écran reste allumé en veille**
→ Le rétroéclairage de certains GC9A01 n'est pas coupé par la mise en veille logicielle. Utilisez le **[NL-401A](./NL-401A-PowerSwitch.md)** pour une coupure physique.

**Les couleurs sont inversées**
→ 🔵 Le champ `invert` de la configuration n'est actuellement pas lu par le firmware (l'inversion est forcée en dur côté code) : le modifier n'a pas d'effet. Un correctif logiciel est nécessaire pour rendre ce comportement configurable — signalez le cas sur le dépôt si votre dalle affiche des couleurs incorrectes.

**L'écran ne s'allume pas**
→ Vérifiez `VCC → 3V3`, `GND` et les GPIO du bus SPI.

---

### 💡 À retenir

- Alimentez l'écran en **3,3 V uniquement**.
- Le bus SPI mobilise six GPIO : anticipez-le avant d'ajouter d'autres modules.
- Le rétroéclairage peut être coupé logiciellement ou physiquement.
- Aucune calibration n'est nécessaire.
- L'inversion des couleurs dépend de la dalle reçue.
