## 🎯 À quoi sert ce module ?

Le BME280 mesure la température de l'air (`t`), l'humidité relative (`h_air`) et la pression atmosphérique (`p`). Il est intéressant pour une **jardinière de radis et plantes aromatiques**, notamment pour observer le climat autour des plantes et alimenter des calculs agroclimatiques dans Natulib OS.

**À ne pas confondre :** ce capteur mesure **l'air**, pas l'humidité du substrat ; il ne remplace pas la sonde capacitive NL-205A. Une mesure à proximité de l'ESP32, d'une lampe ou en plein soleil peut être biaisée. Un **BMP280** ressemble souvent à un BME280, mais ne mesure pas l'humidité relative.

## 🔌 Câblage et branchement

Le BME280 utilise le bus I²C. La carte peut avoir quatre ou six contacts selon le modèle ; **ne pas déduire le brochage de la couleur ou de l'ordre des fils**.

| Contact du module | Destination | Pourquoi |
|---|---|---|
| VCC / VIN | Alimentation compatible avec la carte, idéalement **3,3 V** après vérification | Ne pas supposer que toutes les variantes acceptent 5 V |
| GND | GND commun | Référence électrique |
| SDA | SDA du bus I²C Natulib | Données |
| SCL | SCL du bus I²C Natulib | Horloge |
| CSB / CS (si présent) | Niveau haut selon la notice de la variante | Sélection du mode I²C |
| SDO / ADDR (si présent) | Niveau bas pour 0x76, haut pour 0x77 selon la notice | Sélection d'adresse I²C |

**Important — ESP32-C6 :** l'ancienne fiche proposait SDA=`GPIO4` et SCL=`GPIO5`. Or `natulib_devices.h` marque **GPIO4 et GPIO5 comme broches de strapping** sur ESP32-C6. Ne pas présenter cet exemple comme un câblage par défaut garanti. Il faut choisir une paire de broches **disponibles et validées pour le modèle exact de carte/shield**, puis reporter ces numéros dans la configuration. Le code du driver ne définit pas à lui seul le brochage physique du NL-002A.

**Bus partagé :** BME280, BH1750 et INA219 peuvent partager SDA/SCL/GND/3,3 V si leurs cartes, adresses, résistances de tirage et longueurs de liaison sont compatibles. Le répartiteur I²C et les connecteurs rapides sont des **améliorations envisagées**, pas des accessoires Natulib déjà validés.

**Précaution :** toujours couper l'alimentation avant de modifier le câblage.

## 🚀 Mise en service dans Natulib OS

1. **Flasher** Natulib OS sur l'ESP32-C6, puis accéder à son interface web.
2. **Hors tension**, brancher le BME280 après contrôle de la référence et du brochage.
3. Dans la configuration des périphériques, ajouter un périphérique de type **`bme280`** et lui donner un identifiant unique, par exemple **`climat`**.
4. Sélectionner les GPIO SDA et SCL **validés pour le montage réel** ; choisir un intervalle de lecture.
5. Enregistrer, effectuer le redémarrage requis par l'interface si nécessaire, puis vérifier que le module est détecté.
6. Vérifier les mesures `climat.t`, `climat.h_air`, `climat.p` et l'état `climat.online`.
7. Comparer les mesures avec un instrument de référence ou une observation contrôlée, puis remplir le cahier de validation.

Si le module n'est pas détecté, **ne pas modifier au hasard plusieurs paramètres en même temps** : noter d'abord l'adresse I²C, les broches et le journal de debug.

## ⚙️ Configuration et données Natulib OS

**Exemple de structure JSON — broches à remplacer par celles de ton montage :**

```json
{
  "id": "climat",
  "type": "bme280",
  "pins": {
    "sda": 6,
    "scl": 7
  },
  "interval_ms": 300000,
  "offset": {
    "t": 0.0
  },
  "debug": false
}
```

> `6` et `7` sont **uniquement des valeurs d'exemple de structure**, **pas une validation du brochage du NL-001A/NL-002A**. Adapter après examen du schéma de la carte et des périphériques connectés.

| Champ | Comportement observé dans `DeviceBME280` |
|---|---|
| `id` | Préfixe des mesures (exemple `climat`) |
| `type` | `bme280` : type du périphérique dans la configuration |
| `pins.sda`, `pins.scl` | Nécessaires pour initialiser le bus avec `safeI2CBegin()` ; sans ces champs le driver se désactive |
| `interval_ms` | **300 000 ms (5 min) par défaut** dans `begin()` ; ajustable selon le besoin |
| `offset.t` | Décalage de température appliqué en °C ; **0,0** par défaut |
| `debug` | Journaux de lecture supplémentaires ; **false** par défaut |
| `active` | Paramètre géré au rechargement générique ; vérifier le cycle complet via l'interface |

**Adresse I²C :** le driver teste **0x76 puis 0x77**, sans paramètre `address` configurable dans cette version. Un changement d'adresse s'effectue sur le câblage/PCB de la variante choisie.

**Mesures publiées :**

| Clé | Signification | Unité / interprétation |
|---|---|---|
| `climat.t` | Température après application de `offset.t` | °C |
| `climat.h_air` | Humidité relative | % HR |
| `climat.p` | Pression atmosphérique | hPa |
| `climat.online` | Statut de liaison utilisé dans le cache de mesures | 1 = initialisé, 0 = non prêt |
| `climat.error` | État d'erreur dans le document JSON de l'appareil | `i2c_read_error` après 3 cycles invalides |

Le JSON des trois mesures est arrondi à **une décimale** ; le cache RAM conserve les valeurs flottantes avant arrondi. Le champ `online` est alimenté dans le cache RAM ; sa présence exacte dans toutes les vues/API dépend de la couche de publication Natulib OS.

## 🛠️ Dépannage et fonctionnement du driver

| Symptôme | Première vérification | Comportement du driver |
|---|---|---|
| Aucun capteur à l'initialisation | Alimentation, broches réelles, GND commun, 0x76/0x77, `CSB` | Journal d'absence, puis nouvelles tentatives d'initialisation |
| `online = 0` | Bus I²C et connexion du capteur | État de la liaison dans le cache RAM |
| `i2c_read_error` | Intégrité des signaux, alimentation, connexions intermittentes | Après **3 lectures invalides consécutives**, remise en recherche du périphérique |
| Humidité absente | Référence exacte : BME280 ou BMP280 | Vérifier que le composant est bien un BME280 |
| Température trop haute | Proximité du processeur, soleil, boîtier fermé | Ajustement possible par `offset.t` après comparaison fiable |
| Capteurs I²C instables ensemble | Adresses, pull-up, longueurs de câble, qualité de l'alimentation | Accès au bus protégés par un **mutex I²C** |

Le code considère notamment comme invalides une température non numérique, une humidité non numérique, une pression nulle ou une température hors de la plage de contrôle `−50 °C` à `100 °C`. Ce sont des **critères logiciels de détection**, pas la plage de précision garantie du fabricant.

La gestion du bus I²C et les tentatives de récupération améliorent la robustesse ; elles ne garantissent pas la reconnexion en cas de défaut matériel permanent.

## 🔧 Montage sans soudure — pistes d'amélioration

**Situation actuelle :** certaines variantes BME280 sont vendues sans barrette montée et imposent une soudure. Le shield NL-002A facilite les connexions mais ne supprime pas nécessairement le partage de 3,3 V, GND, SDA et SCL.

- [ ] Tester un câble prêt à brancher et une distribution I²C commune (3,3 V/GND/SDA/SCL).
- [ ] Vérifier le détrompage, la tension, les résistances de tirage et les adresses sur plusieurs modules.
- [ ] Documenter un **montage débutant** sans soudure en parallèle d'un montage avancé.
- [ ] Simplifier ultérieurement la sélection SDA/SCL dans Natulib OS grâce à un profil de shield, après validation matérielle.

**Objectif :** réduire les manipulations sans masquer les règles de sécurité électrique. Ces points sont des **améliorations à tester**, pas des caractéristiques disponibles aujourd'hui.
