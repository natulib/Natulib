**Le BME280 mesure l'ambiance de l'air** : température, humidité relative et pression. Il convient au suivi d'une jardinière, d'une serre ou d'une station météo. Il **ne mesure pas** l'humidité de la terre.

## 🌱 À quoi sert-il ?

- **Température** : suivre les variations autour des plantes.
- **Humidité de l'air** : mieux connaître les conditions de culture.
- **Pression** : suivre l'évolution atmosphérique.

Dans Natulib OS, le driver `bme280` est disponible. **Les essais matériels restent à consigner** pour la carte précise utilisée.

## 🔌 Branchement

| BME280 | Station Natulib |
|---|---|
| VCC / VIN | **3,3 V**, après vérification de la carte du capteur |
| GND | GND commun |
| SDA | Ligne SDA du bus I²C |
| SCL | Ligne SCL du bus I²C |

Le BME280 peut partager le bus I²C avec d'autres capteurs compatibles, notamment le BH1750 ou l'INA219, avec des adresses distinctes. Certaines cartes comportent aussi les broches CS et SDO : suivre **le brochage de la variante réellement achetée**.

> **Avant de brancher :** couper l'alimentation et vérifier les numéros GPIO sur l'ESP32 et le shield. Les valeurs SDA=4 / SCL=5 du modèle d'usine Natulib sont un **exemple de configuration**, pas une garantie de compatibilité avec tous les montages ; le code signale des précautions pour GPIO4 et GPIO5 sur ESP32-C6.

## 🚀 Installation dans Natulib OS

1. Ouvrir l'interface web de la station.
2. Aller dans **Hardware** et choisir **BME280** dans le catalogue.
3. Vérifier le câblage proposé, puis renseigner SDA et SCL selon **son montage réel**.
4. Enregistrer la configuration et redémarrer si l'interface le demande.
5. Consulter les mesures dans **Accueil** ; utiliser **Console** en cas de problème.

L'écran Hardware propose également une **correction de température (offset)**, utile après comparaison avec un thermomètre de référence. Ne pas la modifier sans mesure de comparaison.

## 📊 Ce qu'affiche Natulib

| Mesure | Clé Natulib | Unité |
|---|---|---|
| Température | `mon_bme.t` | °C |
| Humidité de l'air | `mon_bme.h_air` | % |
| Pression | `mon_bme.p` | hPa |
| État de connexion | `mon_bme.online` | 1 / 0 |

*`mon_bme` désigne ici l'identifiant choisi pour le capteur. Le modèle d'usine utilise `meteo_box`.*

## 🧩 Configuration JSON d’usine

Extrait **exact** de `DEFAULT_ORG_BME280` dans `factory_defaults.h` (firmware fourni, V0.448), mis en forme pour la lecture. Il s’agit d’un **exemple**, pas d’un relevé de ton montage : contrôler les broches avant branchement.

```json
{
  "id": "meteo_box",
  "name": "🌡️ Capteur BME280 (Air)",
  "category": "air",
  "type": "bme280",
  "pins": {
    "sda": 4,
    "scl": 5
  },
  "interval_ms": 300000,
  "mA": 1,
  "factory": true,
  "icon": "🌡️",
  "metrics": [
    {
      "id": "t",
      "label": "Température",
      "type": "number",
      "unit": "°C"
    },
    {
      "id": "h_air",
      "label": "Humidité",
      "type": "number",
      "unit": "%"
    },
    {
      "id": "p",
      "label": "Pression",
      "type": "number",
      "unit": "hPa"
    },
    {
      "id": "online",
      "label": "En ligne (capteur actif)",
      "type": "boolean"
    }
  ],
  "actions": []
}
```

### Comprendre les paramètres

| Paramètre | Signification |
|---|---|
| `id` | Identifiant unique du module ; sert de préfixe aux mesures et dans les Synapses. |
| `name` | Nom visible dans l’interface. |
| `category` | Famille utilisée pour organiser les modules dans l’interface. |
| `type` | Type de driver sélectionné par Natulib OS. |
| `pins` | Association entre les fonctions électriques et les GPIO ; **adapter au câblage réel**. |
| `pins.sda` | Ligne de données I²C. |
| `pins.scl` | Ligne d’horloge I²C. |
| `interval_ms` | Intervalle de mesure demandé, en millisecondes (1 000 ms = 1 seconde). Le comportement exact dépend du driver. |
| `mA` | Consommation indicative saisie dans le catalogue, **pas une mesure électrique certifiée**. |
| `factory` | Marqueur de configuration proposée par le catalogue d’usine. |
| `icon` | Icône du module dans l’interface. |
| `metrics` | Liste descriptive des mesures exposées dans Natulib OS (identifiants, intitulés et unités). |
| `actions` | Actions proposées dans l’interface et utilisables selon le driver. |

**Précision issue du driver ou du matériel :** Le driver `DeviceBME280` essaye les adresses I²C `0x76` puis `0x77`. L’option `offset.t` est gérée même si elle n’apparaît pas dans le JSON d’usine. Une perte de liaison entraîne des tentatives de reconnexion.

**Paramètre facultatif du driver absent du JSON d’usine :** `"offset": {"t": 0.0}` (correction de température en °C).

Pour débuter, utiliser l’onglet **Hardware** de Natulib OS : il génère la configuration. La modification manuelle du JSON est facultative.

## 🛠️ Si cela ne fonctionne pas

- **Aucune mesure :** vérifier l'alimentation, le GND commun, SDA/SCL et les contacts.
- **Non détecté :** regarder la **Console** ou utiliser l'outil de recherche I²C ; le driver cherche les adresses `0x76` et `0x77`.
- **Température inattendue :** éloigner le capteur de la chaleur de l'ESP32 et comparer avec une référence.
- **Déconnexion :** le driver retente automatiquement la communication ; vérifier malgré tout le montage physique.

## 🔧 Pour faciliter le montage plus tard

- [ ] Trouver une version du BME280 avec connecteur déjà installé, **sans soudure**.
- [ ] Tester un câble à branchement rapide et détrompé.
- [ ] Simplifier le partage de **3,3 V, GND, SDA et SCL** sur le shield.

Ce sont des **améliorations à étudier**, pas des fonctions déjà validées.

## ⚙️ Pour aller plus loin (facultatif)

Le driver `DeviceBME280` prend en charge `pins.sda`, `pins.scl`, `interval_ms` (**300 000 ms par défaut**), `offset.t` et `debug`. Il publie `t`, `h_air` et `p`, et fournit un état `online` dans le cache de mesures. Après plusieurs lectures invalides, il tente de retrouver le capteur.

La configuration normale se fait dans **Hardware**, sans écrire de JSON. Voir aussi [l'interface Natulib OS](../natulib-os/interface.md) et [les modules et drivers](../natulib-os/drivers.md).
